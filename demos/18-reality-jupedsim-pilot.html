Interpreted stage table · AGE mapping · best practices 
SPELLING
  JuPedSim (Jülich Pedestrian Simulator) — not “JePedSim”.
  Custom Python GP tool on AGE; no out-of-box Esri JuPedSim toolbox.

STAGE → WHAT → WHO (fill) → NOTES
  1  Nominate site
     Facility owner / ops / pilot lead
     Hosted feature layer of candidate sites (attributes: venue, event, floor, AOI)

  2  Fly drone · reality mapping
     Survey / Reality team (Drone2Map or ArcGIS Reality for ArcGIS Pro)
     Ad-hoc missions; control points; CRS + vertical datum locked early

  3  Point cloud from photos · Gaussian splat
     Reality specialist
     Prefer splat (or dense PC) for visual QA before committing to mesh.
     Gaussian splat → 3D Tiles (.3tz); needs ArcGIS Enterprise 12.1+

  4  Mesh generation
     Reality / 3D GIS
     Longer compute. Mesh = analysis-ready surface; splat = photoreal viz.
     Often keep both.

  5  Publish point cloud + mesh (+ splat)
     Publisher / GIS admin
     Point cloud & mesh: SLPK → hosted scene layers.
     Splat: Share as web layer / .3tz → AGE 12.1+ object store.

  6  View: Scene Viewer or CIMS2 (JS Maps SDK 5.x)
     Small planner cohort
     WebScene in Scene Viewer; CIMS2 embeds SceneView / arcgis-scene (5.x).
     SDK 5.0+ favors components; widgets deprecated toward 6.0.

  7  Plan layers (furniture, barricades, assets, ingress/egress, fixtures, blockages)
     Event / safety planners (Creator+)
     Hosted feature layers; floor-aware if Indoors; edit in Scene / custom app.

  8  GP → JuPedSim · realtime / time-aware outputs
     Analyst + platform (custom GP service)
     Export walkable polygons + stages from plan layers → JuPedSim geometry.
     Write trajectories to time-aware features or Stream Layer.
     WebSocket: optional via GeoEvent / stream service for live replay — not required
     for batch “time slider” playback.

  9  Iterate until plan OK
     Planners + ops sign-off
     Revise plan layers → re-run GP → compare density / egress time.

EMERGENCY ROUTING (Wed + Action 29 · D5/C15 · Pilot 02 · HTC2 Thu)
  Need: dynamic routing + real-time traffic for emergency vehicles across
  indoor ↔ outdoor routable networks; HTC2 also wants dynamic rerouting.

  AGE approach
  · ArcGIS Indoors network (pathways + transitions) stitched to outdoor Network Dataset
  · Publish Route / Closest Facility services on AGE
  · Barriers: point / line / polygon — Restriction | Added Cost | Scaled Cost
  · Indoors Viewer: floor-aware + time-aware barriers (START_TIME / END_TIME)
  · “Dynamic”: editable barrier FL + re-solve route (barriers as NA inputs);
    live traffic via traffic feed / GeoEvent when available — not magic on the ND alone

BARRIER GOVERNANCE (gap from Wed)
  Problem: no official point/line/polygon barrier source apparent.
  Fallback: HTX / users self-draw (Julian hopes for authoritative layer elsewhere / SOP).

  Best practices to maintain the barrier list
  1. Authoritative hosted FL (or Indoors-compatible) — not only graphics
  2. Ontology / coded domains: type (closure|hazard|event|construction),
     geometry class (point|line|polygon), severity, mode (walk|vehicle|evac),
     floor / facility, valid_from / valid_to, source_org, status (draft|active|expired)
  3. SOP: who may create/approve/expire; review cadence; link to event tickets
  4. Time-aware + floor-aware so routing only honors active barriers
  5. Until official: self-draw writes into the same schema with status=draft,
     promoted by ops — avoid a second throwaway sketch layer
